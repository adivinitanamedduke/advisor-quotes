# Decisions and trade-offs

Running log of design decisions. The strongest 3 to 5 are summarised in the README "Key decisions and trade-offs" section and expanded in SOLUTION.md.

| ID | Decision | Alternatives considered | Why this one | Trade-off accepted |
|---|---|---|---|---|
| D-01 | Layered projects: API → Business → Data.SQL, with Contracts, Business.Abstractions and Pricing as separate projects | Single project; vertical slice folders | Boundaries are enforced by project references, not convention; Pricing has no reference to quotes so it can become its own service | More projects than a 4 hour exercise strictly needs |
| D-02 | Validation runs in the service (FluentValidation, `ValidateOrThrowAsync` first line), controllers stay thin | Validate in controller or with `[ApiController]` auto validation | Same rules whichever caller reaches the service (HTTP today, a queue consumer later); unit testable without MVC | Model binding errors still come from MVC, mapped to the same error body |
| D-03 | Duplicate handling: honour `Idempotency-Key`; otherwise a SHA-256 fingerprint of adviser + normalised payload inside a time window. Replay returns 200 with the original quote and `Idempotent-Replayed: true`; same key with a different body is 409 | Key only; fingerprint only; unique constraint on business fields | Clients that send a key get exact semantics; clients that forget still avoid double clicks | A deliberate identical re-quote inside the window returns the existing quote |
| D-04 | Concurrency safety in the database: unique index on (adviser, idempotency key) and a transaction scoped advisory lock on the fingerprint | Application level locks; serialisable isolation | Correct across multiple API instances; cheap | One small raw SQL call (`pg_advisory_xact_lock`) in an otherwise LINQ repository |
| D-05 | Status history is its own table, written in the same transaction as the status change; quote row keeps the current status. Optimistic concurrency via Postgres `xmin` | Event sourcing; history as JSON on the quote | Simple to query, cannot drift from the quote, concurrent updates surface as 409 | Two writes per change |
| D-06 | Premium stored with pricing version and the rating factors used | Recalculate on read | A stored quote stays explainable after rates change | Slightly larger rows |
| D-07 | EF Core migrations, applied on startup only when `Database__MigrateOnStartup=true` (on in Development) | Always migrate on startup; separate tool only | One command local run; production keeps migrations as an explicit deploy step | Two paths to document |
| D-08 | One domain model mapped by EF configurations (no separate entity classes) | Separate persistence entities + mapping | Less mapping code for a small domain; Data.SQL still owns all persistence detail via `IEntityTypeConfiguration` | Domain classes have public setters EF needs |
| D-09 | Runtime signal: OpenTelemetry spans plus structured JSON logs stamped with TraceId; `X-Trace-Id` returned on every response | Logs with a custom correlation id only | Standard, vendor neutral, and the same trace id links logs and spans; exporters swap by environment | OTel adds a few packages |
